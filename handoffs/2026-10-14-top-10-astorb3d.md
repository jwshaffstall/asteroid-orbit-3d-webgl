## Ranked Top 10 (all implemented)

- [x] **1. Fix keyboard shortcuts double-firing.** `handleKeydown` was registered on both the canvas and `window`. The canvas has `tabindex="0"` and takes focus on click, so every keydown bubbled canvas → window and ran the handler twice: Space and C toggled twice (appeared broken), R randomized twice, Up/Down changed speed 4x. The handler is now registered on `window` only (`scripts/js/astorb3d.js`), and the stale "Click on canvas first to enable keyboard controls" hint now says shortcuts work anywhere on the page.
- [x] **2. Fix Point Size button silently killing cinematic mode.** The point-size click handler contained a stray `astorb.cinematicMode = { enabled: false, ... }` reset (copy-paste artifact). Clicking "Point Size" disabled cinematic mode and reset its tuning. Removed.
- [x] **3. `astorb2bin.js` reads `.gz` directly.** The repo ships only `astorb/astorb.dat.gz`, but the documented rebuild command referenced `astorb/astorb.dat`, which does not exist in the repo. The converter now streams through `zlib.createGunzip()` when the input ends in `.gz`, so `node tools/astorb2bin.js -i astorb/astorb.dat.gz -o temp/astorb3d.bin` works with no manual gunzip step. Plain `.dat` input is unchanged (verified byte-identical output for both paths).
- [x] **4. Preallocate the per-frame body buffer.** `updateBodies()` allocated a new `Float32Array` every animation frame (60×/s GC churn). The array is now allocated once in `initBodies()` and reused; the per-frame upload uses `gl.bufferSubData` instead of `gl.bufferData`.
- [x] **5. Cache orbit-label path points.** `updateOrbitLabels()` re-ran `computeOrbitPoint` (30 Newton iterations each) for all ~4,300 orbit samples on every frame while labels were on. Orbit geometry is static — only the camera moves — so each label's path is now sampled once in `initOrbitLabels()` and the per-frame work is just a closest-point search plus projection. Identical label placement, ~2 orders of magnitude less math per frame.
- [x] **6. Data-pipeline tool hygiene.** `tools/astorb_line.js` logged "astorb line is not 255 characters" while the constant is 267 — the message now references `AstorbLineLength` so it can't go stale again. `tools/astorb2bin.js`: deprecated `new Buffer()` → `Buffer.alloc()`, `for-in` over the asteroid array → indexed loop, `%d` with a `toFixed()` string → `%s`.
- [x] **7. Unit tests for the line parser.** New `tests/astorb-line.test.mjs`: a valid 267-char line parses to the six expected orbital elements, whitespace-padded fields parse, and wrong-length lines (266/268/empty) return `null`. The parser is the most critical untested component in the repo.
- [x] **8. Fix stale absolute paths in repo `AGENTS.md`.** Three `file:///F:/dev/astorb3d%20-%20Copy/...` links (a local Windows path) replaced with relative links so agent onboarding references resolve.
- [x] **9. README data-pipeline provenance.** Documents the 2013-10-15 osculating-element epoch (data is 13 years old — disclosed, not hidden), why the 35 MB `temp/astorb3d.bin` is intentionally committed (GitHub Pages serves it directly), the binary field layout/order contract, and the corrected one-command rebuild. `project_context.md`'s rebuild command fixed to match.

## Deliberately not changed

- **`temp/astorb3d.bin` stays committed.** Moving 35 MB to Git LFS or a release asset is a real option, but it can't be done cleanly through the file API and would change the live site's fetch path — a maintainer decision, not a drive-by.
- **Jupiter's orbit line vs. the resonance shader.** The asteroid vertex shader applies trojan/hilda libration corrections based on semimajor axis; planet orbit lines are drawn through the same shader, so Jupiter's reference line carries a ≤0.05 rad mean-anomaly wobble. Fixing it needs a shader uniform plus visual verification — flagged, not touched.
- **Per-frame `resizeWebGL()`** in `animate` is cheap (early-outs when size is unchanged) and `ResizeObserver` already handles resizes; left alone.
- **Stats panel always visible** on the live site — arguably dev-only, but possibly intentional for the demo; left alone.
- **Open PRs #23, #24, #29** from other agent branches — not mine to close.
- **`astorb/astorb.txt` is a symlink**; verified it resolves on `raw.githubusercontent.com`, so it isn't broken.
